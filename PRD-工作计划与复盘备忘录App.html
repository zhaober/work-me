PRODUCT REQUIREMENTS DOCUMENT

工作计划与复盘备忘录 App

版本：v1.0（本地版） 日期：2026-08-27 状态：评审中 平台：移动端 Android（基准 360×800）

1. 产品概述

1.1 背景与问题

职场人每天既要规划工作（计划），也要定期总结（复盘）。现有备忘录/笔记工具多为扁平列表，难以把"计划"和"复盘"两类内容按项目或主题归类，也难以在复盘时直接对照原始计划。用户期望一种贴合"文件管理"心智的记录方式：像电脑目录一样层层归档，再在文件夹里沉淀计划与复盘。

1.2 产品定位

一款以「多级文件夹分区 + 计划/复盘双类型」为核心心智模型、采用块编辑器、主打「活力高效」视觉的移动端备忘录 App。让每日计划与复盘结构化沉淀，并能在时间维度（日历/统计）上回顾。

1.3 目标用户

  • 职场白领、项目经理、运营/产品/研发同学；
  • 有"日计划 + 日复盘"习惯、需要按项目/主题归档的人群；
  • 偏好轻量、本地可用、不依赖账号的工具型用户。

1.4 核心价值

  • 双类型分色：计划（靛蓝）/复盘（橙）徽标区分，状态一目了然；
  • 文件式归档：多级文件夹天然贴合"按项目归类"的心智；
  • 计划对照：复盘可关联计划，自动展示完成度对照卡；
  • 灵活记录 + 时间回顾：块编辑器自由书写，日历/统计提供回顾视角。

2. 范围与边界（本版本）

运行模式决策：本版本为本地运行的单机 App，不含云端账号体系，已移除原设计中的「我的 / 云同步」模块。因此"云同步/多设备"功能在本版本暂缓（见 §4 与 §10）。
  • 平台：移动端 Android，基准设计尺寸 360×800；
  • 数据：本地存储（建议 localStorage 或本地数据库），不依赖服务端；
  • 不在本版范围：云端实时同步、多端协同、账号体系、团队协作、AI 自动生成内容。

3. 信息架构与核心概念

3.1 核心对象

  • 文件夹（Folder）：可多级嵌套，类似电脑目录，例如 工作 / 2026 Q3。
  • 计划（Plan）：一条计划记录，含标题、提醒、正文（块）、标签、附件。
  • 复盘（Review）：一条复盘记录，可关联一条计划做对照；含不足说明、改进项、标签。
  • 记录（Record）：Plan 与 Review 的统称，出现在文件夹的"全部记录"列表中。
  • 标签（Tag）：用于分类与统计聚合。

3.2 计划与复盘的关系（混合模型）

  • 两类记录彼此独立，可随时新建，不强制配对；
  • 复盘可关联一条计划，关联后展示"计划对照卡"（计划完成度进度条 + 计划要点），便于复盘时回顾目标。

3.3 信息架构树

首页（文件夹总览） ├─ 文件夹详情 │ ├─ 子文件夹（可继续进入 / 可新建） │ └─ 全部记录（计划·复盘混排，分色徽标） ├─ 计划编辑器 ├─ 复盘编辑器 ├─ 日历视图 └─ 统计看板 底部导航：文件夹 · 日历 · 统计（删除"我的"）

5. 页面与交互设计

5.1 首页（文件夹总览）

结构：状态栏 → 问候+日期 → 搜索栏 → 今日概览（计划/复盘两张卡）→ 文件夹列表（工作/个人/学习）→ 新建文件夹。

交互：点击文件夹行进入对应文件夹详情；点击今日概览卡进入当日记录；底部 Tab 切换。

5.2 文件夹详情

结构：返回/标题/更多页头 → 面包屑 → 子文件夹网格（含「+ 新建文件夹」虚线卡）→ 全部记录（计划 计划 / 复盘 分色）。

交互：子文件夹卡可继续进入下一级；「+ 新建文件夹」可实时新增子文件夹（按当前文件夹隔离）；记录行进入对应编辑器。

5.3 计划编辑器

结构：返回/新建计划/保存页头 → 类型徽标+路径 → 标题 → 提醒（如 18:00 提醒）→ 正文（自由文本）→ 清单块（含勾选态）→ 图片块 → 分割线 → 标签 → 底部块工具栏（文字/清单/图片/分割线/链接）。

5.4 复盘编辑器

结构：橙色 复盘 徽标 → 标题 → 关联计划卡（"已关联计划 / 完成 Q3 新品上线方案"）→ 正文 → 计划对照卡（完成度进度条）→ 不足说明 → 改进项块 → 标签。

交互：关联计划卡点击可重新选择/解除关联。

5.5 日历视图

结构：月份导航（2026年8月）→ 月历网格（今日 27 高亮）→ 选中日面板（如"8月27日·周四，今日 2 条"）→ 当日记录列表。

交互：点击日期切换选中日面板；记录行进入编辑器。

5.6 统计看板

结构：标题 + 周期切换（本周 ▾）→ 完成率卡（78%，18/23）→ 小指标（复盘篇数 12 / 连续复盘 5 天）→ 7 日趋势柱状图 → 标签分布卡。

交互：周期切换刷新统计；标签分布可点击下钻。

  • 卡片圆角 14–16；计划/复盘徽标 6；文件夹图标 10；头像 24；复选框 5；开关 13；进度条 3；图片块 12；

  • 内容容器内边距 20/20/16；模块间距 16–18；状态栏高 36；底部 Tab 高 95；编辑工具栏高 64。

6.3 字体

全局字体 Inter（中文回退 PingFang SC / 微软雅黑）。标题 18–20、正文 14–15、次要 12–13。

6.4 风格基调

活力高效：卡片化、轻投影、主题色点缀，类似 Todoist / 飞书的轻快观感。

7. 数据结构（本地）

Folder { id, name, parentId, color, createdAt } Record { id, type: 'plan' | 'review', folderId, title, blocks: Block[], tags: string[], reminder?: string, // 如 "18:00" linkedPlanId?: string, // 仅 review 使用 createdAt, updatedAt } Block { type: 'text'|'checklist'|'image'|'divider'|'link', text?, checked?, src?, href? } Tag { id, name, color }

8. 非功能需求

  • 性能：冷启动 < 1s；列表滚动 60fps；统计计算 < 200ms。
  • 兼容：Android 9+，主流机型与分辨率自适应（以 360×800 为基准）。
  • 存储：本地存储，图片建议压缩后入库，单用户建议上限 200MB。
  • 可访问性：文字与背景对比度满足 WCAG AA；交互元素有清晰点击区（≥ 44px）。

10. 开放问题与风险

  • 云同步是否纳入后续版本？当前本地版不含；若需多设备，需补充账号体系（F-13）。
  • 子文件夹嵌套深度是否限制（建议 ≤ 4 级，避免路径过深）？
  • 图片存储策略：本地压缩阈值、是否允许外部图床？
  • 统计口径："完成率"如何定义（按勾选清单 / 按计划标记完成）需产品确认。
  • 提醒可靠性：本地通知在 App 退出后的触达能力依赖系统，需评估。
