PRODUCT REQUIREMENTS DOCUMENT

工作计划与复盘备忘录 App

版本：v1.5.5（本地版 · 后台通知修复 + 文字颜色自定义） 日期：2026-08-30 状态：已实现并交付 Android Debug APK；含真机反馈修复（v1.5.0）、启动稳定性专项（v1.5.1）、闪退根因修复（v1.5.3，经 logcat 定位 `cancel({})` 空载荷 NPE）、插件调用看门狗（v1.5.4）、后台通知修复与文字颜色自定义（v1.5.5） 平台：移动端 Android（基准 360×800）

1. 产品概述

1.1 背景与问题

职场人每天既要规划工作（计划），也要定期总结（复盘）。现有备忘录/笔记工具多为扁平列表，难以把"计划"和"复盘"两类内容按项目或主题归类，也难以在复盘时直接对照原始计划。用户期望一种贴合"文件管理"心智的记录方式：像电脑目录一样层层归档，再在文件夹里沉淀计划与复盘；同时希望 App 具备个性化能力（主题、音效、风格、自定义背景），贴合自身审美与习惯。

1.2 产品定位

一款以「多级文件夹分区 + 计划/复盘双类型」为核心心智模型、采用块编辑器、主打「活力高效」视觉，并支持 个性化（主题 / 音效 / 风格 / 背景） 的移动端备忘录 App。让每日计划与复盘结构化沉淀，并能在时间维度（日历/统计）上回顾，且不背单词式的轻量沉浸体验。

1.3 目标用户

  • 职场白领、项目经理、运营/产品/研发同学；
  • 有"日计划 + 日复盘"习惯、需要按项目/主题归档的人群；
  • 偏好轻量、本地可用、不依赖账号、且重视个性化观感的工具型用户。

1.4 核心价值

  • 双类型分色：计划（靛蓝）/复盘（橙）徽标区分，状态一目了然；
  • 文件式归档：多级文件夹天然贴合"按项目归类"的心智；
  • 计划对照：复盘可关联计划，自动展示完成度对照卡；
  • 灵活记录 + 时间回顾：块编辑器自由书写，日历/统计提供回顾视角；
  • 个性化表达：浅/深主题、交互音效、多套 UI 风格、自定义背景，体验更"像自己的"。

2. 范围与边界（本版本）

运行模式决策：本版本为本地运行的单机 App，不含云端账号体系，"云同步/多设备"功能在本版本暂缓（见 §4 与 §10）。
v1.2 边界变更（反转旧决策）：原 v1.1 曾"删除「我的」、底部导航仅 3 个 Tab"。依最新需求，重新引入「我的」个性化中心（第 4 个底部 Tab + 侧边栏入口），并采用 「侧边栏为主、底部 Tab 为辅」 导航形态；主题、音效、UI 风格、自定义背景均纳入本版本。
  • 平台：移动端 Android，基准设计尺寸 360×800；
  • 数据：本地存储（v1.4 起为 IndexedDB，见 §7），不依赖服务端；
  • 不在本版范围：云端实时同步、多端协同、账号体系、团队协作、AI 自动生成内容；
  • 已重新纳入：「我的」个人中心、侧边栏导航；已删除/暂缓：云同步/多设备。

3. 信息架构与核心概念

3.1 核心对象

  • 文件夹（Folder）：可无限层级嵌套，类似电脑目录，例如 工作 / 2026 Q3 / 新品上线。
  • 计划（Plan）：一条计划记录，含标题、提醒、正文（块）、标签、附件、优先级（高/中/低）。
  • 复盘（Review）：一条复盘记录，可关联一条计划做对照；含不足说明、改进项、标签。
  • 记录（Record）：Plan 与 Review 的统称，出现在文件夹的"全部记录"列表中。
  • 标签（Tag）：用于分类与统计聚合，可点击删除。
  • 重要日子（Event）：用户自定义的重要日期（亲友生日/纪念日），周年重复，日历专属标记。
  • 我的 / 设置（Me）：个性化中心，承载主题、音效、背景、重要日子管理、导出（v1.2 新增）。
  • 主题与风格（Theme/Style）：浅色/深色主题，以及视觉风格（默认 / 液态玻璃 / 极简 / 景深），由 CSS 变量驱动（v1.2 新增）。

3.2 计划与复盘的关系（混合模型）

  • 两类记录彼此独立，可随时新建，不强制配对；
  • 复盘可关联一条计划，关联后展示"计划对照卡"（完成度进度条 + 计划要点）；
  • v1.2 新增优先级：计划/复盘可标记优先级（高/中/低），用于文件夹内快速识别与"优先级归纳"查看。

3.3 信息架构树

侧边栏（主导航，左抽屉） ├─ 首页（文件夹总览） │ ├─ 文件夹详情 │ │ ├─ 子文件夹（进入 / 新建 / 重命名 / 删除 / 选择性删除 / 一键清空） │ │ └─ 全部记录（计划·复盘分色，含优先级徽标） │ │ └─ 优先级归纳视图（高/中/低 分组） │ ├─ 计划编辑器（含删除、优先级选择器） │ └─ 复盘编辑器（含删除、关联计划） ├─ 日历视图（含节气 / 节日 / 自定义重要日子标记） ├─ 统计看板 └─ 我的（主题·音效·背景·重要日子·导出） 底部导航（辅助）：文件夹 · 日历 · 统计 · 我的

5. 页面与交互设计

5.1 首页（文件夹总览）

结构：问候+日期 → 搜索栏 → 今日概览（计划/复盘两张卡）→ 文件夹列表 → 新建文件夹。

交互：点击文件夹进入详情；今日概览卡进当日记录；侧边栏/底部 Tab 切换屏；每日首次启动弹名人名言。

5.2 文件夹详情

结构：返回/标题/更多页头 → 面包屑 → 子文件夹网格（含「+ 新建」虚线卡）→ 全部记录（计划 计划 / 复盘 分色，含优先级徽标）。

交互：子文件夹可进入下一级；"..."菜单：重命名 / 选择性删除 / 一键清空 / 删除；提供「优先级归纳」按钮按高/中/低分组。

5.3 计划编辑器

结构：返回/类型徽标/路径 → 标题 → 提醒 → 优先级分段选择器（高/中/低） → 正文 → 清单块 → 图片块（点击查看大图）→ 分割线 → 标签 → 底部块工具栏；标题栏含保存与删除。

交互：优先级点击切换；图片点击全屏预览/替换/删除；标签「+添加」；保存写回 DB。

5.4 复盘编辑器

结构：橙色 复盘 徽标 → 标题 → 关联计划卡 → 正文 → 计划对照卡（完成度进度条）→ 不足说明 → 改进项块 → 标签。

交互：关联计划卡点击重新选择/解除关联，自动渲染完成度对比卡。

5.5 日历视图

结构：月份导航 → 月历网格（今日高亮 + 节气/节日/重要日子彩色圆点）→ 选中日面板（当日记录 + 节气/节日/重要日子列表 + 「＋ 添加重要日子」）→ 当日记录列表。

交互：左右翻月跨年；标题点击输年份月份跳转；「＋ 添加重要日子」登记亲友生日等。

5.6 统计看板

结构：标题 + 周期切换 → 完成率卡 → 小指标（复盘篇数 / 连续天数）→ 7 日趋势柱状图 → 标签分布卡。

交互：周期切换刷新统计；标签分布可点击下钻。

5.7 侧边栏导航（v1.2）

结构：左抽屉，顶部应用名；中部导航项（首页/日历/统计/我的）+ 文件夹快捷入口；底部（设置/关于）。

交互：左滑或点汉堡唤出；点击跳转并同步底部 Tab 选中态；点遮罩/选中项关闭；文件夹快捷入口直达详情。

5.8 我的（个性化中心，v1.2）

结构：信息头 → 设置分组：主题（浅/深）、音效（开/关）、背景（上传自定义图，上传即压缩）、重要日子（管理）、导出文件夹（选目标目录，可恢复默认，F-20）、存储优化（图片占用展示 + 一键优化，F-25）、UI 风格（默认/液态玻璃/极简/景深，规划中）、导出（导出后告知位置，F-19）。

交互：设置即时生效并持久化（settings）；背景已落地并压缩；UI 风格多套切换为 F-18 规划项；导出目录句柄持久化于 IndexedDB。

7. 数据结构（本地）

7.1 IndexedDB 表结构（v1.4）

库名 work-memo-idb，版本 1，共 4 个对象仓库：

notes（主表，keyPath: id） { id, type, folderId, title, date, time, reminder, priority, image_id, update_time } 索引：by_update(update_time) / by_folder(folderId) / by_date(date) —— 列表页只扫这张表，不含正文 note_contents（正文表，keyPath: id） { id, content_compressed: Uint8Array, style_data: Uint8Array } —— content_compressed = LZString.compressToUint8Array(JSON({body, checklist})) —— style_data = TextEncoder(JSON({tags})) // 小字段，不压缩 —— 分表原因：IndexedDB 游标一次取整行，同表无法做到「列表不加载正文」 note_images（图片表，keyPath: id） { id, note_id, hash_sha, blob_full: Blob, blob_thumb: Blob, w, h, bytes, created } 索引：by_hash(hash_sha, unique) / by_note(note_id) —— Blob 直存，不做 Base64（体积 +33% 且整块进内存） meta（键值表，keyPath: k） { k, v } —— folders / events / settings / migratedFrom

图片入库管线（compressImage）：

  1. createImageBitmap 解码（不可用回落 Image）；
  2. 大图：长边缩放到 1080，canvas.toBlob('image/webp', 0.75)；
  3. 缩略图：200×200 居中裁剪，toBlob('image/webp', 0.65)；
  4. crypto.subtle.digest('SHA-256') 计算哈希 → 查 by_hash 唯一索引 → 命中则复用旧 id、放弃本次 Blob 存储；
  5. WebP 不支持时回落 JPEG（避免浏览器静默降级成 PNG 反而更大）；crypto.subtle 不可用（非安全上下文）时回落 FNV 指纹，去重不中断。

运行时以内存中的 DB 为唯一渲染源；图片 Blob 渲染前转 URL.createObjectURL，带缓存与释放（releaseUnusedImageUrls）。

7.2 业务对象（内存 / 代码视图）

Folder { id, name, parentId, color, createdAt } Record { id, type: 'plan' | 'review', folderId, title, blocks: Block[], tags: string[], reminder?: string, // 如 "18:00" linkedPlanId?: string, // 仅 review priority?: 0|1|2|3, // v1.2：0 无 / 1 高 / 2 中 / 3 低 createdAt, updatedAt } Block { type: 'text'|'checklist'|'image'|'divider'|'link', text?, checked?, src?, href? } Tag { id, name, color } Event { id, name, month, day, date?, color?, createdAt } // v1.2 重要日子 Settings { // v1.2 个性化；v1.3 增强 theme: 'light'|'dark', style: 'default'|'liquid-glass'|'minimal'|'depth', bgImage?: dataURL, // 自定义背景（已压缩入库） soundOn: bool, reminderPlan?: { startMin, intervalMin, stopMin, includeTarget } // 多级提醒方案（F-23） } // 导出目录句柄持久化于 IndexedDB（非 settings），运行时恢复
存储约束（v1.4 已根本性改善）：
  • 配额：v1.4 起业务数据存 IndexedDB，不再受 localStorage 约 5MB 配额限制。
  • 正文：经 lz-string 压缩为 Uint8Array，重复中文实测压缩到约 5%，且列表查询不加载正文。
  • 图片：WebP Blob 直存 + SHA-256 全局去重，同图反复插入只占一份空间；严禁 toDataURL 产出存储用图（toDataURL 仅用于 1×1 画布的 WebP 格式探测）。自定义背景仍为压缩后的 dataURL（settings.bgImage，最长边 1280 / JPEG 0.72）。
  • 写入：防抖 3000ms + 切后台强制落盘；编辑已有记录自动存草稿。新建记录不自动入库，返回键 = 放弃未保存改动。
  • 删除：删笔记先删关联图片再删记录；写盘时按差集清理内存中已删除的记录，避免幽灵数据；提供 cleanupOrphanImages 清理孤儿 Blob。
  • 空间释放（Web 局限）：IndexedDB 删除记录后不会自动归还磁盘空间，浏览器按源整体管理，代码层面无法强制收缩；可在开发者工具中清除站点数据。因图片已压缩到最小，实际影响有限。
  • 降级：IndexedDB 不可用时自动降级 localStorage，App 不白屏。

8. 非功能需求

  • 性能：冷启动 < 1s；列表 60fps；液态玻璃 backdrop-filter 低端机需降级评估。
  • 兼容：Android 9+，主流机型自适应（以 360×800 为基准）。
  • 存储：v1.4 起业务数据存 IndexedDB（正文 lz-string 压缩、图片 WebP Blob + SHA-256 去重），localStorage 仅作降级通道；单用户建议上限 200MB。
  • 可测试性：核心逻辑抽为纯函数模块，npm test（Node Test Runner）一键跑全量回归，含 IndexedDB 集成测试。
  • 可访问性：对比度满足 WCAG AA；点击区 ≥ 44px；深色主题需校准对比度。
  • 一致性：弹窗用自定义 Modal / Action Sheet，禁止系统 prompt/confirm；音效统一可关。

10. 开放问题与风险

  • 提醒可靠性（v1.5.0 已接入原生通知）：已集成 @capacitor/local-notifications（F-34），保存/删除/启动时同步系统层通知，App 退出或进程被杀后仍可收到提醒。剩余限制：
    • 国产 ROM 后台管控：小米/华为/OPPO 等需用户手动开启「允许后台运行」「自启动」，否则系统会拦截 AlarmManager 唤醒；
    • 精确闹钟：已声明 SCHEDULE_EXACT_ALARM，但 Android 12+ 用户仍可在系统设置中关闭，关闭后提醒可能延迟；
    • 插件版本差：@capacitor/local-notifications 官方最新为 7.0.0，与 @capacitor/core 7.6.8 存在版本差（官方更新滞后），当前运行无异常。
  • 启动稳定性（v1.5.4 已彻底修复）：v1.5.1 消除「白屏/打不开」三类主因（远程字体渲染阻塞 F-36、存储层挂起无超时 F-37、崩溃无可见反馈 F-35）；但 v1.5.1 的修复方向有误——真机 logcat 显示闪退真正根因是 LocalNotifications.cancel({}) 空载荷触发 Java 层 NPE（v1.5.3 修复），而非 Web 层问题。v1.5.4 进一步加插件调用看门狗：所有原生插件调用调用前留痕、成功后清除，若进程在 Java 线程被带崩，下次启动崩溃面板会点名嫌疑调用，使「沉默闪退」变为可诊断。
  • 云同步是否纳入后续版本？ 当前本地版不含；若需多设备，需补充账号体系（F-13）。
  • 存储容量（v1.4 已解除硬约束）：业务数据迁至 IndexedDB 后不再受 localStorage ~5MB 配额限制。剩余风险：① IndexedDB 删除记录后不自动归还磁盘空间（按源整体管理，代码无法强制收缩，需手动清除站点数据）；② crypto.subtle 仅在 https / localhost 可用，file:// 下去重回落 FNV 指纹；③ 跨笔记去重复用图片时删除持有者会留下孤儿记录，由 cleanupOrphanImages 清理。
  • 迁移风险：localStorage → IndexedDB 为一次性迁移，靠 meta 标记保证幂等；迁移后保留 localStorage 副本作回滚保险，不主动删除。
  • 统计口径："完成率"按勾选清单计算（已确认）。
  • v1.2 新增：深色主题逐屏校准；液态玻璃低端机降级；侧边栏与底部 Tab 路由同步；多风格以 CSS 变量隔离避免污染。
